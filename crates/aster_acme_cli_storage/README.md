# aster_acme_cli_storage

CLI 的账户文件存储适配，实现 `dyn AccountStore` 和 `dyn AccountKeyStore`。`toml_file` 模块另提供有界读取与缺失配置的加锁、原子初始化；配置 schema 和注释模板由 CLI 定义。`aster_acme` 不依赖本 crate；嵌入式 Aster 服务可提供数据库存储和软件/远程签名器。

文件实现包含 Unix 和 Windows 适配。Unix 保留 owner/mode 与 no-follow 检查；Windows 沿用继承权限，不管理专用 ACL，并检查 reparse point 与托管文件硬链接。锁使用 Rust 1.89+ 标准库。Windows 构建检查与原生运行验收分别记录。

布局：

```text
<data-dir>/
  config.toml              # 根 version=1 与 [config]，用户设置
  config.toml.lock         # 配置初始化和读改写共用的锁
  .locks/
    daemon/
      instance.lock        # 同一 data-dir 的常驻 daemon 独占租约
  accounts/
    personal/
      account.toml         # 根 version=1 与 [account]，程序维护
      account-key.pk8      # P-256 PKCS#8 DER 私钥
    work/
      account.toml
      account-key.pk8
```

每个名称绑定一个 CA directory 和公钥指纹，名称在本地唯一；显式换 CA 或指纹不匹配时拒绝，不隐式生成新身份。无需 CA 摘要层、names.toml、active-account.toml 或 initialized。`account switch` 更新 config.toml 的 default_account。

`toml_file` 统一有界读取、有限等待锁、取消后的 guard 生命周期、原子替换及文件/目录 sync。配置在锁内读取最新文本再用 toml_edit 修改；账户操作的 lease 覆盖远端请求和持久化，不重复获取自己的锁。锁载体释放后保留，其存在不代表持锁。配置 schema 和模板属于 CLI；账户 schema 属于账户适配器。

- 目录 `0700`、文件 `0600`，拒绝不安全目录、符号链接、硬链接或错误属主。
- macOS 并发首次创建 no-follow 锁文件可能返回 ENOENT；通过同一校验目录描述符重试一次，保留链接和权限检查。
- 使用固定 registry 版本的 标准库非阻塞锁加有限等待；锁 guard 释放后关闭句柄。
- Unix 文件操作复用 Forge `StateDirectory`，以目录描述符执行 no-follow 打开和原子替换，sync 文件及目录。
- 配置上限 64 KiB，首次写入为 `0600`；已有只读公开配置可为 `0644`，拒绝其他用户可写、链接或错误属主文件。读取不会改动已有目录权限；初始化锁等待有上限，取消后工作线程仍持锁完成原子写入。
- 账户元数据使用 TOML，默认选择保存在配置里，私钥继续使用 PKCS#8 DER。尚未正式发布，不读取或迁移旧 JSON 及旧目录布局，不提供兼容入口。旧目录不会自动清理或移动。
- 元数据 schema 版本为 1；未知版本、损坏 TOML、超限文件均报错，不自动重置。
- 私钥按名称保存后才进入账户注册。取消、超时、注册失败不删除私钥；注册意图与成功元数据分别持久化。
- 恢复/查看使用 `KeyAccess::Existing`，不生成密钥。已有账户记录但私钥缺失/损坏或指纹不符时拒绝换钥；孤立私钥也拒绝猜测 CA。先持久化账户身份再写私钥，记录本身代替初始化标记，崩溃后失败关闭。
- 元数据上限 256 KiB，私钥上限 64 KiB，锁默认由调用方设置，允许 0–300 秒之间的非零时长。
- 私钥文件依靠 OS 权限保护，当前不提供静态加密。备份时必须把私钥和元数据一起作为敏感数据保护。

覆盖重启复用、CA/名称隔离、锁冲突/超时/释放、文件损坏/超限/未知 schema、权限、链接拒绝及丢钥不替换。依赖仅从根 workspace 继承。MIT OR Apache-2.0.

account.toml 首行为 `# Managed by aster-acme. DO NOT EDIT this file.`，根版本与 `[account]` 之间空行。`contacts` 为本地设置，`server_contacts` 独立记录 CA 可选返回，不把服务端遗漏当作本地输入丢失。

账户元数据保留 last_status 和 deactivation 状态（not_requested/pending/confirmed）。列表复用 accounts 枚举，返回注册阶段、最后 CA 状态和本地可用性，不加载密钥。停用不删除数据；已停用/撤销或 pending 意图不会作为可用账户供 switch 选择。未发布阶段直接更新 schema，无迁移旧账户格式。

`CliAccountStore::remove` 只处理已知托管账户文件，额外用户文件或目录不影响删除。无额外内容时持锁 rename 到隐藏清理目录再 unlink；有额外内容时保留原目录及外置锁 inode，先移除 account.toml，再删除已知私钥/轮换文件，用户内容不动。托管文件的不安全链接、锁超时与既有异常清理目录仍报错。CLI 负责确认和条件清理默认配置，不向 CA 停用账户。

时间字段通过 AccountTimes 在 [account] 下保存 registered_at、last_status_at、last_used_at，采用 UTC RFC 3339；未知值省略。文件适配器和枚举只保留服务提供的时间，不在读取/写盘/删除时自行更新；账户服务统一处理时钟与观察事件。

## 轮换事务

AccountRotationStore 返回持有账户锁的 dyn AccountRotation：同一进程/跨进程串行，stage 持久化 `account-key.next.pk8`；metadata.key_rotation 保存 new_thumbprint 和 pending/confirmed。CA 确认后先备份旧钥到 `account-key.previous.pk8`，再原子替换 primary，最后写入新指纹并清除日志。两个附加文件保留到下一次持锁打开，主钥与已提交元数据一致才清理。中途失败不丢旧钥；confirmed 重启可从备份加载旧身份并重新提交。

所有阻塞写入持有 Arc<FileLease>，取消上层 future 不释放正在写入的账户锁。未确认、同钥、指纹不符、身份变更、丢失 staged key 或不安全文件均拒绝提交；remove 允许安全删除上述已知事务文件，不调用 CA。元数据可选 user_agent 只保存显式账户偏好，无值时不写入；默认值由客户端决定。

## 证书世代

```text
certs/<certificate-name>/
  cert.toml                         # version + [cert]，name/in_use
  in_use -> <UTC-time>-<random8>/
  <UTC-time>-<random8>/
    operation.toml                  # journal version=1 + [operation]，时间/账户/CA/状态/receipt
    private-key.pk8                 # 证书私钥，不是账户私钥
    request.der                     # 固定 PKCS#10 CSR
    material.sha256                 # 固定 key/CSR 的完整性绑定
    fullchain.pem                   # 完整 CA 返回链
    cert.pem                        # 叶子证书
    ca.pem                          # 剩余 CA 返回链，叶子单独返回时为空
    private-key.pem                 # 同一证书私钥的 PEM PKCS#8
```

证书默认名是主域名加随机后缀，碰撞重试；显式已有名称拒绝；显式名称仍需满足单目录组件规则。每次申请有独立 ID 和 UTC created_at，同名可有多个未完成申请；in_use 只指向已经校验并落盘的版本，失败不覆盖旧版。operation 保存 CA expires、原始 Location、授权/通知阶段、全部手动 TXT 和待清理标记，不含凭据。

锁顺序为账户→证书。后台阻塞写任务保留 Arc 租约，调用 future 取消也不会提前解锁。初始化先写可列举的 journal，再写私钥/CSR/哈希，缺失材料拒绝恢复、不静默生成新身份。落盘按 完整产物集合→Downloading journal→原子 in_use 链接→cert.toml 选择→Completed journal 完成；任一中间失败可重新下载同一订单证书，不重新签发。普通读取不加载私钥，执行恢复会验证材料/路径/权限/版本/数量上限；未知版本和损坏不迁移。预发布字段布局不保留兼容读取；本地测试记录需手动按当前schema更新。保留旧世代，目前不自动清理历史证书。

目录扫描仅以 cert.toml/operation.toml 识别托管对象，忽略 .DS_Store、笔记、额外目录和未识别链接；已识别托管文件仍严格检查类型、身份、schema、权限和尺寸。in_use 是唯一显式托管的相对 symlink，只可指向同级且身份匹配的世代；不覆盖用户同名普通文件或指向外部的链接。版本名为 UTC 秒级创建时间 + 8 位随机后缀，完整 operation ID 留在 journal，不保留旧目录布局读取。

续期计划和证书吊销的职责、持久化及失败边界见 [生命周期契约](../../docs/certificate-lifecycle.md)。ARI提供计划、显式刷新及由cron调用的`daemon run-once`；常驻CLI daemon通过独立的data-dir租约保证单实例。吊销保留本地文件，与订单状态独立。

cert remove 默认选一次申请，--history 清理非当前已签发版本，--revoked 匹配已确认吊销，--all 删除整个名称；默认否确认、脚本 --yes，不访问 CA 或账户；保留用户额外内容，根目录 .locks 保持稳定锁 inode。清理中断通过 .removing 标记阻止复用残留，见生命周期契约。account/cert show 用 CA query 指明本次实际查询范围，已确认吊销依据单列为 saved CA response。

托管身份、稳定定义、默认 in_use 展示与历史版本的最终契约见生命周期文档。IssueStore::create 只新建身份，IssueStore::renew 为已有定义准备新版本；cert renew 提供单次执行，常驻维护由CLI宿主执行并持有单实例租约。

证书 key_algorithm 使用公共 KeyAlgorithm 枚举，CLI -k/--key-type 默认 ecdsa-p256；定义、版本、恢复和实际密钥保持一致。RevocationReason 统一 RFC 5280 已分配代码（无7），CA 自行决定接受范围；remove-from-crl 不代表 ACME 恢复。详见生命周期契约。

0.1.0-alpha.1 提供 cert renew 单次到期/--now 提前续期，使用稳定定义、持久化 predecessor/replaces、未完成恢复和成功后 in_use 切换；`daemon run-once`执行一个周期，`daemon run`以前台常驻方式按配置间隔循环，默认60秒，同一data-dir由跨进程租约限制为单实例。两者刷新ARI建议，自动续期到期的webroot/standalone/tls_alpn证书并执行已配置部署；manual验证会跳过。对象锁集中于根 .locks/accounts、.locks/certificates与.locks/daemon，完整移除对象后清空无额外用户内容的目录，外置锁 inode 保留。

账户元数据必需保存 key_algorithm；AccountKeyStore 使用 KeyAccess::Existing/Create(Option<KeyAlgorithm>)，真实 PKCS#8、指纹及保存类型必须一致。轮换缺省继承原类型；暂存钥存在时恢复其实际类型，显式不同选择拒绝。只有确认换钥提交才原子更新主钥和算法字段，常规 save 不能修改算法；无旧 schema 默认值或迁移。


## 平台机制与上游归属

当前使用标准库文件锁，不再直接依赖 AsterFs。state_file 是临时的跨平台文件适配，模块顶部 TODO 关联 AsterFs #3/#4；上游能力尚未交付，不保留 fs2/fs4 转发接口。普通文件 IO 保持标准库，缺失的句柄相对打开/平台文件身份/同步原语将按上游实际 API 接入。

Windows 继承目录权限，不管理 ACL。in_use 使用四份完整 PEM 副本与 .generation 标记；同级 staging/previous 目录保证可按 catalog 恢复，双 rename 不是跨平台原子交换。Unix 继续使用链接，两个平台的 CLI 输出路径都为 in_use 下的四个文件。复制模式的正常、失败、回滚、用户内容保留测试在每个主机执行，Windows 原生结果由 CI 单独提供。

证书定义和每个版本新增必需challenge/solver_id/solver_config；HTTP webroot保存规范绝对路径，manual实现保存空配置。open/save/renew均校验不可变定义，未知修改拒绝；未发布格式无旧读取/迁移。授权材料为按method区分的validation，保留cleanup_pending；清理成功后保存，不因清理失败回滚已完成产物。

## 查询与源码所有权

`account.rs` / `account/{rotation,removal}` 拥有账户文件实现；`inventory.rs` 拥有轻量账户查询。`issuance/generation.rs` 拥有生成和续期准备，`issuance/session.rs` 拥有持锁会话与提交，`issuance/query.rs` 拥有证书文件查询，`issuance/deployment.rs` 拥有发布及检查点。上层契约在 `aster_acme::storage`，不做旧导入路径转发。

`query_accounts(root, AccountQuery)` 返回 `Vec<LocalAccount>`，按 name/directory/state/usable/operation 做 AND 筛选；明确 name 时直接读该账户，列表不加载密钥或查询 CA。`IssueStore::query(IssueQuery)` 返回 `Vec<IssueRecord>`；默认枚举所有版本，支持 name/operation/in_use/phase/unfinished/revocation/resumable/similar。`IssueView::{All,Managed,CurrentOrUnfinished}` 先选择版本，再应用状态谓词。Managed 选 in_use，否则最新未完成，否则最新历史；不会把历史标成当前使用。

明确 name 直接访问对应目录，operation 或 in_use 限制使适配器按目录中的 ID 前缀裁剪 journal 读取；无索引的文件后端仍需枚举该目录，状态条件仍需解析候选 metadata。全目录/全历史查询继续拒绝范围内损坏资料，不隐藏错误；有界路径/文件数量和大小限制保持。查询只是快照，部署/续期/移除持租约后必须复查状态。账户 list --verify 更新每条查询所得的观察，不再二次全目录扫描。

证书查询的 `deployment_count` 与 `is_in_use` 都是本地库存快照，从已读取的 cert.toml 填充，不额外逐项获取绑定。`deployment_count = None` 表示适配器未提供该信息；文件适配器返回精确数量（包括0），历史/当前版本共享所属托管证书的配置数量。该字段不写入 operation.toml 或 ACME wire/证书结果 JSON。

部署的 `DeploymentPermissions` 保存可选Unix证书文件/私钥mode，缺省0600；Windows继承权限并拒绝显式mode。`DeploymentPatch` 仅更新给出的字段，目标替换整个目的路径集合，配置变化后重置为Configured，不发布、不reload。add/update/open按跨证书配置锁→证书租约顺序检查目的路径冲突；禁止覆盖其他绑定或托管账户/证书/控制文件，open后只保留证书租约。配置锁仅序列化目标所有权变动/检查，不跨reload持有。

发布逻辑位于 `issuance/deployment/publication`，先为全部选定文件在各自父目录准备临时文件、写入内容、应用mode并同步，全部成功后才逐文件替换。准备失败时现有目标不变，已准备临时文件由所有权guard清理；提交前重新检查整组目标，拒绝期间出现的目录/链接。提交中途失败可能留下部分更新，后续显式重试重新发布完整选定集合；只有全部替换和目录同步成功后，CLI才执行reload。直接发布普通文件并保留父目录，不创建部署链接或交换目录；默认私钥不会被证书文件mode放宽，不承诺整组原子切换。进程崩溃可能遗留临时文件，不扫描删除仅凭文件名前缀匹配的内容。失败保留路径、IO阶段及OS原因；阻塞写入任务继续持有证书租约直到完成。存储不执行reload，不保存进程stdout/stderr；调用方分别报告本次执行失败和历史检查点。

精确文件部署支持独立可选的 certificate/private_key/ca_chain/fullchain 四类路径；任意非空子集合法，不要求证书和私钥配对。None 不发布该文件；指定目标预检后只替换对应文件。仅保留绝对路径、目标互不重复及与目录模式互斥的安全边界。配置中的原证书/私钥字符串字段继续可读，新可选字段缺省为 None，不改变原有绑定及续期行为。

Windows持久化边界：替换前同步临时文件，成功表示进程级替换完成并支持进程重启恢复；目录同步当前只验证目录可访问，不保证断电后rename目录项落盘。Unix文件及父目录同步有更强保证；不要把Windows进程崩溃恢复等同掉电事务。

账户写入接口显式持锁：`AccountStore::lock_account` 返回 `Arc<dyn AccountLease>`，`AccountStore::save(record, &lease)` 把同一租约克隆进阻塞写任务；不使用隐藏store状态寻找当前锁，也不在协议写入内重获锁。`CliAccountStore::save(record)` 是独立本地编辑入口，会自行新获取租约。轮换会话内部串行化stage/save/commit，确认快照变化拒绝操作；删除要求调用方传入确认过的AccountRecord身份。


## 独立吊销会话

`CliIssueStore::open_revocation(name, operation_id)`返回持有证书执行租约的`ManagedRevocationSession`。其`RevocationSession`实现只加载已签发叶子及journal，不要求CSR、material.sha256、证书当前有效或原账户存在。`certificate_signer()`仅在明确选择certificate-key时以受限读取加载保存的PKCS#8，校验保存算法后返回`Arc<dyn JwsSigner>`；账户模式不读取这份私钥。

会话固定打开时的叶子DER，在每次checkpoint写入时重新核对文件指纹和不可变托管身份；确认后文件替换拒绝提交，已confirmed检查点不可覆盖。阻塞读写持有IO许可及证书租约直到结束。完整签发执行的`IssueStore::open`仍检查CSR/私钥/证书有效性，两者不混用；确认结果由certificate_record读取最新快照，CA请求只在服务库执行。
