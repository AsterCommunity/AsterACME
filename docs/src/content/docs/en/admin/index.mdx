## Operating principles

**Keep the data directory private**: private keys, account profiles, and provider credentials all live under the data-dir. Give the service user exclusive access; on Unix the CLI sets key files to `0600`, but directory access control is the operator's responsibility.

**Least-privilege credentials**: DNS provider tokens should carry Zone Read + DNS Edit for the target zones only; `--allow-zone` is an extra guard rail, not a substitute for minimizing the credentials themselves.

**Review reload commands**: reload runs without a shell as a fixed argv, but the process still starts with the runner's privileges. Review the command before configuring it; its output is displayed verbatim, never auto-redacted.

**Staging before production**: when onboarding a new DNS provider executable or validation chain, walk through the full issuance, recovery, and cleanup flow against Let's Encrypt staging (`--ca-directory`) and a zone you control before switching to the production CA.
