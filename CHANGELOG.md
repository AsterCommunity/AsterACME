## [Unreleased]

Initial pre-release. ACME packages are not published; Rust APIs and local formats may change without compatibility readers or automatic migration.

### Added

- **DNS Persist (experimental)** — Support `draft-ietf-acme-dns-persist-02` through `-c dns_persist`: validate issuer metadata, prove account control with authenticated POST-as-GET, and derive domain/key/account-bound SHA-256 hashed TXT records, including wildcard scope and multi-string presentation. Provision manually once; keep records after validation and reuse confirmed, unchanged publication across restart, renewal, account rollover, and unattended maintenance. Changed records require manual action. Legacy draft spellings are retained but not executed; DNS provider writes and public-CA acceptance remain separate.

- **Accounts** — Named CA accounts with registration, key-based recovery, contact updates, key rotation, deactivation, and local removal. Support Let's Encrypt, ZeroSSL, Google, custom directories, explicit terms consent, EAB, and independent account/certificate key choices.
- **Certificate issuance** — Single-domain, SAN, and wildcard requests with manual DNS-01, manual/webroot/standalone HTTP-01, and standalone TLS-ALPN-01. Persist fixed keys, CSRs, challenge material, and CA submission evidence for recovery without silently creating another order.
- **Issuance journal format** — Rename the persisted NewOrder checkpoint to `new_order_intent_saved`, name saved challenge material `validation_requirement`, and derive leaf expiry from the renewal plan instead of storing it twice. Keep the pre-release journal version number at 1; earlier field layouts are not read or migrated.
- **Renewal and revocation** — Foreground single/batch renewal, saved-definition reuse, ARI window sampling and Retry-After, and randomized validity-based fallback (half for certificates shorter than ten days, otherwise two thirds). Retain plans on query failures, renew expired predecessors, stop ARI queries after expiry, and support explicit account or certificate-key revocation via `cert revoke --sign-with account|certificate-key`. Certificate-key mode works without the original account, while account mode needs no certificate private key or CSR; expired certificates remain eligible for CA consideration. Persist the exact DER fingerprint, CA, reason and signing identity at the submission boundary, distinguish unsent work from uncertain results, and preserve local files. Revocation uses an independent session contract; public signing APIs are now `JwsSigner` and `SoftwareSigningKey` without legacy aliases.
- **Scheduled certificate maintenance** — `daemon run-once` performs one cycle; `daemon run` stays in the foreground and repeats it after a configurable delay (default 60 seconds). Hold an exclusive cross-process lease per data directory, stream timestamped human logs or JSON Lines, and stop cooperatively on Ctrl-C/SIGTERM without overlapping cycles. Both modes refresh due ARI suggestions, renew eligible `webroot`, `standalone`, `tls_alpn`, and provisioned `dns_persist` certificates, and retry configured deployments. Persist renewal failure backoff at 1 minute, 10 minutes, 100 minutes, then daily; keep CA `Retry-After` as a lower bound, preserve the previous in-use certificate, and block new orders when a newOrder outcome is uncertain. Persist deployment retry deadlines separately and retry known publish/reload failures without renewing again; recheck binding snapshots, generations, and deadlines under the execution lease before publishing or reloading. Include preparation errors and elapsed operation budgets in renewal backoff, while user cancellation and lease contention leave failure counts unchanged; stale workers cannot overwrite newer retry state. Never automatically replay uncertain reloads. Reuse existing renewal and deployment transactions, per-certificate budgets, and cross-process leases; administrators can request early retries with `cert renew --now` or `--all --now`. Manual validation is skipped.
- **Deployment** — Multiple named bindings with standard PEM directories or independent artifact paths, optional Unix file/key modes, automatic deployment after issuance/renewal, and offline list/show/update/remove commands. Prepare and sync every selected file before individual replacement; anchor Unix publication and cleanup to opened parent directories, and reload only after full publication. Await started publications on manual or automatic cancellation; validate certificate/key identity before publication, retain uncertain reload outcomes across configuration and generation changes without replay, distinguish interruption before process startup, and preserve deployment reports on cancellation. Bound reload attempts, deadlines, process cleanup, and stdout/stderr capture; continue other targets on failure and retain issued certificates.
- **CLI** — `cert remove NAME --failed` cleans up terminally failed unissued requests while preserving issued, resumable and uncertain operations. Interactive input, scoped arguments, offline inventory, metadata-only account inspection without private keys, explicit CA verification, shared UTC progress/tables, JSON reports, build metadata, and safe debug stages. Configure request timeout, operation timeout, poll interval, and poll limits independently; show poll counts and Retry-After wait sources. Resolve the shared state root with `--data-dir`, `ASTER_ACME_DATA_DIR`, then the platform default.
- **CAA prechecks** — Advisory checks before new orders in issue/renew, using advertised CA identities, inherited CAA policy, wildcard precedence and account/method constraints. Unmatched records, unknown extensions, DNS failures and timeouts never block CA validation. Feature-gated, explicitly invoked CAA/TXT/HTTP checkers share the embeddable runner, default five-second stage budget and cancellation policy, with structured reports retaining partial observations. Preserve system-resolver initialization stages and underlying causes in CAA/TXT diagnostics; distinguish missing CA identities from local initialization failures. Keep system DNS configuration and upstream Hickory unchanged, without fallback resolvers. Libraries default to no prechecks; CLI enables them by default.
- **Protocol diagnostics** — Typed ACME resources and all 32 IANA error types with RFC/draft references, unknown-extension preservation, identifier subproblems, exact ARI explanationURL mapping, bounded expiry-spanning renewal windows, and persisted rejection/uncertainty evidence. Check the live IANA registry weekly.
- **Embedding and documentation** — Object-safe signer/store/solver/observer contracts, named per-method material modules, centralized method admission/publication policies, typed retained-validation snapshots, project and CLI contracts, task routing, module design guides, RFC references, and separate local/staging validation records.
- **Repository governance automation** — Adopt the organization-shared, SHA-pinned `AsterCommunity/aster-automation` Action with repository-owned `.github/aster-automation.json`: path-proven labels (`Rust`, `Python`, `Documentation`, `Dependencies`, `Scope: Core|Protocol|Client|Crypto|Challenges|Storage|CLI|Deployment`, `Risk: High`), linked-issue lifecycle (`Priority:*`, `Status:*`, `Wait For PR`, `Merged`), an aggregated `PR Gate` with CI lifecycle labels and in-place diagnostic comments, fingerprinted default-branch/scheduled failure issues with flaky and infrastructure classification, hourly reconciliation that also syncs label definitions, issue templates that pre-tag new reports, and a release readiness dashboard. `Repository Automation` validates the configuration and the workflow static contract on every automation change.

### Changed

- **Recovery and concurrency** — Carry explicit shared account leases through blocking writes; serialize rollover IO, retain submission ownership through caller cancellation, and bind confirmations to the inspected identity. Reconcile confirmed rollover locally, preserve old challenge material across account key changes, restore certificate views from the durable catalog, and reject stale promotion. Run ARI, due renewal, and deployment retry stages through the library maintenance coordinator; keep filesystem leases in storage and reload execution in the host. Share cancellation/deadlines through CA discovery and automatic deployment; preserve committed batch results.
- **Publication and cleanup** — Deploy regular files at stable directory paths without links, directory swaps, or a whole-set atomicity guarantee. Pin webroot directory identities with rename-blocking Windows sharing access, sync new directory permissions, and drain blocking workers on shutdown; reuse the HTTP pool for advisory probes, honoring operator proxies and internal destinations with a shared fixed five-second DNS/HTTP precheck budget; accept trailing ASCII whitespace in HTTP-01 responses. Webroot cleanup verifies the actual isolated object before deletion and retains user replacements. Manual validation uses native inquire confirmation with visible input/editing and default no. Prompt readers are joined and cancellation/deadlines are rechecked after input; inquire restores terminal mode; diagnostic write/flush failures cannot report success.
- **Storage and portability** — Versioned TOML, bounded typed queries, standard-library locks, and platform-specific file validation. Unix uses private permissions and relative internal in_use links; Windows uses inherited permissions and recoverable complete-directory copies. Sync new Unix state-directory entries before remote mutations; never recreate deleted accounts through metadata saves. Windows process-restart recovery does not imply power-loss durability of rename metadata. Preserve unrelated user files.
- **Runtime and dependencies** — Share lazy HTTP connections while isolating account policy and nonce state. Centralize dependency versions/features and enforce rustls/AWS-LC. Optimize release size and install the Forge panic hook only in the executable, with private redacted reports and no mutation retries.
- **Build and CI** — Check Linux, macOS, and Windows; enforce import ownership, dependency features, and local documentation links and independent optional-precheck feature combinations, including proof that disabled builds exclude the DNS resolver. Decode source, manifests, and Cargo output as UTF-8 independently of Windows locale. Avoid unrelated parent-repository revisions and missing packed-reference watch paths; build dirty covers tracked changes only. A Linux coverage job collects `cargo-llvm-cov` LCOV output, publishes a per-run summary, and uploads it to Codecov.

Automated DNS provider publication remains unimplemented. Cross-compilation and local mocks do not constitute native-platform or public-CA acceptance.
