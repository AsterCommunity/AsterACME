## [Unreleased]

### Added

- **IANA error registry tracking** — Map all 32 registered ACME error types with RFC/draft references and actionable diagnostics; check the official CSV weekly and on relevant pull requests without storing a registry snapshot.

- **Validation failure diagnostics** — Persist newOrder error status/problem/Retry-After independently of Order status, distinguish rejected/deferred/unconfirmed creation and exclude response failures from resume. Preserve non-400 badCSR responses, reconcile orderNotReady through order queries, and retain terminal authorization/challenge problems with safe cleanup and recovery refusal. Display embedded CA order/challenge problems and identifier subproblems, retain invalid orders for inspection and reject their recovery without advertising resume. Webroot INFO reports actual published/reused/retained/removed paths; debug explains server URL-to-file mapping. Confirmed invalid orders clean up owned unchanged webroot files through the shared terminal-outcome lifecycle; cleanup failures retain pending state and the original CA problem, while uncertain/cancelled operations keep their files.

- **Configurable polling interval** — Default local CA polling to 5 seconds; config poll_interval and --poll-interval independently override it without shortening a valid CA Retry-After.

- **HTTP redirect prechecks and wait visibility** — Advisory HTTP-01 checks follow bounded HTTP/HTTPS redirects while signed ACME requests remain redirect-free. Show every poll wait source and add parsed Retry-After to safe debug metadata.

- **Explicit limit defaults** — Configure request_timeout, operation_timeout and max_polls in config.toml; CLI --request-timeout/--operation-timeout/--max-polls override them independently. Remove ambiguous timeout/wait-timeout names without aliases or migration.

- **Bounded CA polling** — Add --max-polls with per-round counters, persisted Retry-After/local-interval wait sources and resumable limit failures; skip already-valid authorization refreshes. HTTP publication gets a bounded advisory content check through the shared HTTP pool.

- **Method-driven HTTP validation** — One ACME protocol flow accepts CLI-owned manual DNS, manual HTTP, webroot and standalone implementations. Standalone reuses Tokio/Hyper HTTP/1 with no web framework or new resolved crates; persist `--listen-address` (default `0.0.0.0:80`), serve exact Host/path GETs, bound connections and release the listener on every outcome. Restore acknowledged challenges without replay and share temporary-listener lifecycle with future TLS-ALPN. Persist immutable method/configuration/material through resume and renewal; webroot publishes exact HTTP-01 content with durable file-identity ownership, preserves existing/changed files and keeps cleanup failures separate from issued certificates. Add full-definition unfinished-request selection and --if-similar-order automation, including unconfirmed creation guidance without replaying newOrder. Local DNS is now a bounded advisory precheck; skip/force options are removed. Progress identifies the managed name, implementation and protocol. Add --debug safe checkpoint/request-metadata diagnostics and reject deterministic recovery failures before CA discovery. Unreleased storage/JSON formats change without compatibility readers.

- **Account key algorithms** — Share eight key choices between account and certificate generation; add `account register/rotate-key -k/--key-type`, typed ES256/ES384/ES512/EdDSA/RS256 signatures, canonical EC/RSA/OKP JWKs and account key-type metadata/views. Default new accounts to P-256; preserve staged keys across cross-algorithm rollover and reject conflicting choices. Unreleased account metadata requires `key_algorithm` without legacy readers. Standard help entrypoints share formatting without reinterpreting positional values.

- **Single and batch renewal** — Add cert renew and sequential `--all` batches with per-item outcomes, one structured summary and concise human results without duplicate plan/check logs, partial-failure/cancellation exit statuses, nonblocking manual TXT tasks, and due-time checks, --now for early execution, saved-definition reuse, restart-safe predecessor/replaces tracking, and atomic in_use promotion. Resume unfinished renewals; preserve old artifacts on failure. Use a bounded advisory DNS precheck without skip/force bypass options. Keep object locks outside deletable directories; remove empty account/certificate directories while preserving user content. Use enum-derived result output and resource-scoped query evidence. All workspace packages independently declare 0.1.0-alpha.1; no daemon is started.

- **Certificate key choices and revocation reasons** — Add a shared eight-choice certificate key enum and `-k/--key-type` (ECDSA P-256 default), including P-384/P-521, Ed25519, and RSA 2048/3072/4096/8192. Persist and validate the choice through recovery and renewal preparation; show it in progress and certificate views. Use typed RFC 5280 reason codes without a client CA-policy allowlist; preserve CA rejection details. Persist explicit badCSR rejections so recovery retains the original failure even if another request completes the same CA order; display a red local failed status separately from the CA order status; typed RFC 8555 problem enums preserve unknown extensions and share actionable CLI diagnostics, including rate-limit hints and identifier subproblems.

- **Renewal planning and certificate revocation** — Fetch RFC 9773 ARI after issuance, persist a uniform random renewal time and Retry-After refresh deadline, retain valid plans on errors, and use a randomized one-day fallback window before the two-thirds validity target (one-half for certificates shorter than 10 days), clamped to local plan creation time. Add account-signed `cert revoke` with exact-generation selection, optional reason, explicit confirmation, durable uncertain/confirmed states and retained local files. Periodic wakeups and automatic renewal remain future daemon work.

- **ACME account management** — Register and recover named accounts, inspect offline or verify with the CA, update contacts, rotate keys with durable reconciliation, deactivate accounts, and remove local managed files. Support public CA presets, custom directories, explicit terms consent, EAB, account-scoped User-Agent, and default selection without overwriting concurrent changes.
- **Manual DNS certificate issuance** — `cert issue` handles orders, SAN/wildcard authorization, manual TXT requirements, optional DNS visibility checks, fixed certificate keys/CSRs, finalization, download, and artifact validation. Resume saved requests by certificate name with explicit request selection for ambiguity. `-y/--yes` skips the TXT confirmation on resume while retaining DNS checks; Local DNS errors/missing values only warn and continue after confirmation. Fresh automated requests first return TXT instructions. `cert list/show` remains read-only unless explicitly refreshing CA observations with `--verify`.
- **Recoverable private storage** — Versioned TOML, standard-library file locks, bounded reads, atomic writes, and immutable key/CSR binding. Readable timestamped certificate versions retain full-chain, leaf, CA-chain, and private-key PEM files behind an atomic `in_use` link. Failed validation or writes do not replace the selected certificate; unrelated user files are preserved. Managed names are independent of primary domains: automatic suffix collisions retry, explicit existing names refuse reuse, and stable definitions own renewal generations. List/show default to in_use; explicit history retains full SANs without active renewal schedules. `cert remove` selects one request or explicit history/revoked/all scopes, preserves unrelated versions and user files, clears in_use without promoting history, and marks interrupted cleanup.
- **CLI interaction and automation** — Shared storage/HTTP argument groups, meaningful short options, explicit validation-method selection for new issuance and general operation confirmation with `--yes`, missing-input guidance including interactive bare `cert issue --resume`, bounded advisory DNS observations, default-no confirmations, compact request selectors, aligned colored details/tables, fixed UTC times, resource-scoped query markers, typed progress, JSON output, and build/version metadata. The [CLI contract](docs/cli-contract.md) defines confirmation, force, consent, and command scopes.
- **Embeddable protocol layers** — Pure state decisions, typed ACME resources/JWS/problems, exact discovered URLs, ES256/HS256, bounded nonce retries, timeout/cancellation handling, and object-safe signer/store/readiness/observer contracts. Unknown challenge extensions are retained without imposing DNS-01-specific token requirements. Validation implementations are organized by method in `aster_acme_validation`.

- **TLS-ALPN-01 validation** — Add a temporary RFC 8737 listener with persisted `tls_alpn` configuration, SNI and `acme-tls/1` gating, per-domain self-signed challenge certificates, critical `id-pe-acmeIdentifier` digests, resumable publication and terminal cleanup. Reuse the bounded Tokio/rustls listener lifecycle; ordinary certificate keys are never exposed.

### Changed

- **Standard-library locks and platform storage** — Remove the lock-only AsterFs dependency in favor of Rust standard file locks. Centralize file policy in a platform adapter; Windows inherits permissions without requiring ACL management and publishes complete in_use PEM copies with recoverable staging/previous-directory swaps. Retain Unix links and permission checks, use portable managed names, and add native OS CI targets. Missing low-level mechanisms are tracked by AsterFs #3/#4; directory swaps are recoverable, not guaranteed atomic exchanges.

- **Command output and HTTP lifecycle** — One command-scoped output session owns progress, prompts and final results across account/certificate/version commands, with independent stream colors, conditional separators and one JSON report even on partial failure. A lazy shared HTTP pool is retained by ACME clients across batch operations; account User-Agent, request deadlines and nonce state stay isolated.
- **Dependency and TLS ownership** — Forge HTTP uses published `=0.1.0-alpha.2` with only JSON, rustls/AWS-LC, and system-proxy features; utils/macros remain on `=0.1.0-alpha.1`, file locks use Rust standard APIs without AsterFs, and base64 uses 0.23.1. Rustls and the shared AWS-LC crypto backend avoid duplicate P-256 stacks. The client explicitly selects rustls even if an embedding application unifies another backend. CI rejects native-tls/OpenSSL transport dependencies. Every crate owns its package version; dependency versions, sources, and features remain centralized in the workspace. Production feature allowlists audit Cargo feature unification in CI, reject alternate TLS/crypto backends and unused HTTP/UI/logging features, and keep only crossterm/fuzzy prompts plus fmt/ANSI/env-filter logging.
- **Release builds** — Optimize the CLI and its dependencies for size with `opt-level="z"`, LTO, and one codegen unit. Keep unwind panics and function symbols while excluding source-level debug information. The executable installs published Forge panic `=0.1.0-alpha.2` before Tokio starts. Private redacted reports use `<data-dir>/crash.log`; public human/JSON errors never include panic payloads or backtraces. Libraries do not install hooks. Report writes reject unsafe files, use nonblocking locks and a 1 MiB cap; failures preserve keys/checkpoints and do not trigger mutation retries.
- **Documentation** — Bilingual README and changelog, the project website, crate guides, RFC references, architecture, CLI contracts, and separate local/staging validation records. Automated DNS publication, daemon scheduling, and deployment remain unimplemented.
