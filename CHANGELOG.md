# Changelog

## [Unreleased]

### Added

- Dedicated `aster_acme_protocol` crate centralizes typed request/response, public provider directory presets, discovered URL, problem and JWS contracts. Protocol requests and CLI JSON reports serialize named structures; callers import models directly without legacy re-exports.
- ACME account registration, key-based recovery, authenticated inspection, and irreversible deactivation with durable uncertain-result handling with ES256 JWS, explicit terms acceptance, HS256 EAB, bounded badNonce retries, response limits, timeouts, and structured CA errors. Pure core decisions drive account lifecycle eligibility and transitions. UTC registration-confirmation, status-observation, and last-use timestamps update only on successful account responses. Local contact settings are retained separately from optional CA contact responses. Object-safe signer/store interfaces support embedded services.
- CLI account commands with public CA presets and custom `--ca-directory`, production Let’s Encrypt defaults, unified data-directory configuration, command-scoped flags, shared interactive account selection with a create-first registration action menu, custom User-Agent, plain-email contact input normalized to ACME URIs, boolean consent recording the discovered terms URL, aligned account listing with highlighted default selection and optional per-account verification, offline inspection with explicit `--verify`, shared positional/named account targets, local-only account removal, concise action summaries, named accounts bound to individual CAs with comment-preserving default switching, explicit reuse notices and default-no interactive account reuse and current-terms confirmation, optional validated email prompts (`--yes` for reuse in automation, separate `--accept-terms` for consent), platform default unified state directory with automatically initialized versioned TOML configuration and persisted explicit registration contacts, colored terminal diagnostics, structured JSON output, and a version command exposing build-time revision, dirty state, target, profile, features and timestamp. A separate Unix file-storage adapter with private PKCS#8 keys, versioned TOML metadata and account selection, one directory per local account name containing its key and metadata, CA/key identity checks, bounded AsterFs locking, and Forge descriptor-based atomic state writes. Interrupted registration retains its key and intent for recovery; missing initialized account keys are never silently replaced.

- Pure ACME resource-state decisions and upper-layer DNS identifiers, challenge selection/material derivation, and injectable solver contracts with versioned recovery receipts. Known and unknown wire values, input boundaries, and selection combinations have regression coverage; network issuance and concrete solvers remain unimplemented.

- Rust workspace packages and crate directories use underscore names; the executable remains `aster-acme`. Workspace includes protocol core, client orchestration, DNS solver, and CLI crate boundaries. Dependencies and Forge-aligned strict lints are managed at the workspace root. Certificate operations are not implemented yet.
