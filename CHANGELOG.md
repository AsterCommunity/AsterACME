## [Unreleased]

### Added

- **Huawei Cloud DNS** — Include the backend in the default CLI build; embedded hosts opt in with `huawei_cloud`. `project_id` is optional and is discovered through IAM for the selected region; `region` is optional and defaults to `cn-north-4`. Public-zone discovery, HWS signatures and durable RRset recovery use best-effort ownership: concurrent external changes between read and PUT/DELETE may be overwritten or deleted; atomic isolation is not guaranteed (#41).

- **Alibaba Cloud DNS and Tencent Cloud DNSPod** — Included in default CLI builds, with individual features `dns-aliyun` and `dns-tencent-cloud` for smaller builds. Both save the final target’s zone, the observed TXT TTL and verify the exact record before cleanup. Built-in providers use a shared marker contract with provider overrides; Alibaba Cloud uses the 50-character-safe `acme-<publication_id>` form while the default remains `asteracme-<publication_id>`. Alibaba Cloud writes its marker with `UpdateDomainRecordRemark` after creation and retries that checkpoint without repeating TXT creation. DNSPod reconciles lost creates using publication remarks. Alibaba Cloud DNS requests detailed domain attributes to discover its minimum TTL, recognizes documented record statuses, requires the saved create-response record ID and refuses to borrow existing values. (#40, #39)

- **Embedded issuance example** — `cargo run -p aster_acme --example embedded_issuance` walks the full embedding path: CA discovery, account registration or reuse through `AccountService`, an embedder-owned HTTP-01 webroot `ChallengeSolver`, saved-request resume via the `IssueStore` contract, and promoted artifacts. The example defaults to Let's Encrypt staging with a temporary data directory, compiles under workspace CI, and the bilingual README quick starts link it as the library-first entry point (#33).
- **DNS publication TTL** — Configure requested TXT TTL with `provider add/update --ttl-seconds` (default 120, RFC 2181 range 0–2147483647); retain each publication's saved TTL across recovery and profile edits. Backends own vendor-specific limits; local propagation observations keep their existing advisory behavior.
- **Automatic CA terms updates** — `account register --auto-accept-new-terms` accepts the current directory terms and durably delegates future terms URL changes for unattended account ensure and renewal. The exact accepted URL remains visible in `account show`; `--yes`, JSON mode and implicit ensure never enable the delegation.

### Changed

- **DNS provider diagnostics** — Include the API action, HTTP status, validated provider error code, and safe request ID in native backend failures when available. Raw response bodies and provider messages remain hidden; the same CLI path also displays safe provider codes from external backends.

- **DNS read reconciliation** — Share bounded read retry budgets across native providers while retaining vendor-specific visibility and ownership checks. Never replay an uncertain creation or treat malformed responses and identity conflicts as visibility delays.

- **DNS HTTP effects** — `HttpRequest.method` now uses the shared `HttpMethod` enum, with an optional provider-owned operation name for diagnostics. Built-in adapter paths move to `provider::vendors`; shared support remains internal under `provider::common`. Vendor Cargo features automatically select shared implementation capabilities; HTTP method variants no longer depend on vendor flags.

- **Deployment verification** — Verify the full published file set against staged content, identity and applicable permissions before reload. Report completed replacement paths on failure while retaining the partial-set/retry contract; no whole-set atomicity or automatic rollback is promised. Refuse configuration and deployment when an existing destination cannot be normalized to prove ownership; restore access or remove the stale binding before retrying.
- **Optional validation dependencies** — An empty `aster_acme_validation` feature set no longer brings Tokio into production dependencies. Check and test optional feature combinations independently.

### Fixed

- **ACME mutation recovery** — Retain revocation Pending and challenge/finalize Submitted evidence after 408/429 instead of treating these transient responses as definitive rejection. Preserve acknowledgement/finalize retry deadlines, prior uncertain revocations and the existing explicit-retry boundaries.
- **Maintenance diagnostics** — Preserve both the refresh failure and subsequent durable-read failure for one certificate, report its latest schedule as unavailable, and continue processing the remaining certificates.

## [0.1.0-alpha.2] - 2026-11-18

### Added

- **Release pipeline** — Publish version tags automatically: a draft GitHub release with changelog-extracted notes, `aster-acme` binaries for linux amd64+arm64 (static musl), macos amd64+arm64, and windows amd64+arm64, each with a per-version symbol archive (macOS UUID pairing via `dwarfdump`, Linux GNU build-id debug files, Windows PDB sidecars) for offline backtrace resolution (#9), signed multi-arch Alpine container images on GHCR and Docker Hub where `latest` tracks stable tags only, and a Homebrew tap formula update for every release. Include cargo-binstall metadata mapping release assets per target.

- **Native DNS backends** — Discover backend-owned configuration and factories through one validated registry. Add feature-selected Cloudflare (`cloudflare` in the embedding crate, CLI `dns-cloudflare`) with optional zone pinning or discovery from the final CNAME target, durable per-publication zone identity, publication-comment reconciliation, private token files, and exact owned-record cleanup. Providers emit versioned HTTP/checkpoint effects; hosts execute them with bounded Forge transport and durable per-publication/RRset leases. Include a conditional RRset state machine that preserves unrelated values and metadata, retries only proven revision conflicts, and retains uncertain ownership. Real DNS/public-CA acceptance remains separate.

### Changed

- **DNS configuration** — Use `dns_provider` for both native and ADPP backends, expose `provider backends` and private `--settings-file` inputs, display backend IDs in profile lists, list `dns_provider` first in the interactive validation menu, and allow per-requested-domain explicit DNS publication targets. Profiles require `backend_id` and `backend_config_version`; saved certificate definitions pin backend/configuration version and non-sensitive remote binding. Old `dns_external` definitions and prior profile layouts are retained but not automatically read or migrated. ADPP v1 requests now carry the final record name without CNAME routing fields; external providers must adapt to this pre-release wire change.

- **CI triggers** — Run push checks only on `main` and pull request checks only for `main`; cancel superseded runs for the same PR or branch to avoid duplicate branch/PR checks.

- **Forge process execution** — Replace the retired `aster_acme_process` with published `aster_forge_process = 0.1.0-alpha.3` for bounded child-process lifecycle mechanics. ADPP and deployment retain their protocol and side-effect policies; incomplete tree cleanup overrides direct-child success, preserves uncertain side effects, and forbids automatic replay.

## [0.1.0-alpha.1] - 2026-11-16

Initial pre-release. Rust APIs and local formats may change without compatibility readers or automatic migration.

### Added

- **Cloudflare ADPP example provider** — Ship `examples/dns-providers/cloudflare_adpp.py`, a stdlib-only Python 3.9 external provider implementing ADPP v1 `present`/`cleanup` against Cloudflare: longest-suffix zone discovery with optional pinned zone, idempotent republication keyed by the record `comment`, pre-existing exact values retained as `preexisting` and never deleted, cleanup that verifies the exact record ID plus value before deleting and fails closed on mismatch, and mapped `authentication_failed`/`authorization_denied`/`rate_limited`/`provider_unavailable` errors. Credentials come from `provider_custom` (`api_token` or `token_file`, optional `zone_id`, test-only `api_base`); local mock tests run without network access and are wired into CI.

- **External DNS providers (ADPP)** — Configure private per-profile files with `provider add/list/show/update/remove`, issue and renew with `-c dns_external --provider NAME`, and retry terminal cleanup with `provider cleanup NAME`. Allow all valid publication domains by default, with optional `--allow-zone` restrictions and `--clear-zones` to remove them. Freeze CNAME routing before mutation; persist exact per-record receipts and rate-limit lower bounds before CA acknowledgement. Preserve pre-existing TXT values, partial successes, and uncertain outcomes. Custom profile values are sensitive, passed only on stdin and redacted from reports; child processes inherit no environment. Share process-tree ownership and bounded I/O with deployment reload through an independent process crate. Built-in DNS vendor clients and real-DNS/staging acceptance remain separate.

- **DNS Persist (experimental)** — Support `draft-ietf-acme-dns-persist-02` through `-c dns_persist`: validate issuer metadata, compare `issuerDomainNames` as an order-independent set, prove account control with authenticated POST-as-GET, and derive domain/key/account-bound SHA-256 hashed TXT records, including wildcard scope and multi-string presentation. Provision manually once; keep records after validation and reuse confirmed, unchanged publication across restart, renewal, account rollover, and unattended maintenance. Changed records require manual action. Legacy draft spellings are retained but not executed; DNS provider writes and public-CA acceptance remain separate.

- **Accounts** — Named CA accounts with registration, key-based recovery, contact updates, key rotation, deactivation, and local removal. Support Let's Encrypt, ZeroSSL, Google, custom directories, explicit terms consent, EAB, and independent account/certificate key choices.
- **Certificate issuance** — Single-domain, SAN, and wildcard requests with manual DNS-01, manual/webroot/standalone HTTP-01, and standalone TLS-ALPN-01. Persist fixed keys, CSRs, challenge material, and CA submission evidence for recovery without silently creating another order.
- **Issuance journal format** — Rename the persisted NewOrder checkpoint to `new_order_intent_saved`, name saved challenge material `validation_requirement`, and derive leaf expiry from the renewal plan instead of storing it twice. Keep the pre-release journal version number at 1; earlier field layouts are not read or migrated.
- **Renewal and revocation** — Foreground single/batch renewal, saved-definition reuse, ARI window sampling and Retry-After, and randomized validity-based fallback (half for certificates shorter than ten days, otherwise two thirds). Retain plans on query failures, renew expired predecessors, stop ARI queries after expiry, and support explicit account or certificate-key revocation via `cert revoke --sign-with account|certificate-key`. Certificate-key mode works without the original account, while account mode needs no certificate private key or CSR; expired certificates remain eligible for CA consideration. Persist the exact DER fingerprint, CA, reason and signing identity at the submission boundary, distinguish unsent work from uncertain results, and preserve local files. Revocation uses an independent session contract; public signing APIs are now `JwsSigner` and `SoftwareSigningKey` without legacy aliases.
- **Scheduled certificate maintenance** — `daemon run-once` performs one cycle; `daemon run` stays in the foreground and repeats it after a configurable delay (default 60 seconds). Hold an exclusive cross-process lease per data directory, stream timestamped human logs or JSON Lines, and stop cooperatively on Ctrl-C/SIGTERM without overlapping cycles. Both modes refresh due ARI suggestions, renew eligible `webroot`, `standalone`, `tls_alpn`, `dns_external`, and provisioned `dns_persist` certificates, and retry configured deployments. Persist renewal failure backoff at 1 minute, 10 minutes, 100 minutes, then daily; keep CA `Retry-After` as a lower bound, preserve the previous in-use certificate, and block new orders when a newOrder outcome is uncertain. Persist deployment retry deadlines separately and retry known publish/reload failures without renewing again; recheck binding snapshots, generations, and deadlines under the execution lease before publishing or reloading. Include preparation errors and elapsed operation budgets in renewal backoff, while user cancellation and lease contention leave failure counts unchanged; stale workers cannot overwrite newer retry state. Never automatically replay uncertain reloads. Reuse existing renewal and deployment transactions, per-certificate budgets, and cross-process leases; administrators can request early retries with `cert renew --now` or `--all --now`. Manual validation is skipped.
- **Deployment** — Multiple named bindings with standard PEM directories or independent artifact paths, optional Unix file/key modes, automatic deployment after issuance/renewal, and offline list/show/update/remove commands. Prepare and sync every selected file before individual replacement; anchor Unix publication and cleanup to opened parent directories, and reload only after full publication. Persist a separate pending-generation intent before automatic publication so daemon maintenance can resume after cancellation or restart without treating the previous generation as deployed. Await started publications on manual or automatic cancellation; retain uncertain reload outcomes across configuration and generation changes without replay, restore the complete prior generation/retry checkpoint when cancellation precedes a side effect, and preserve deployment reports. Bound reload attempts, deadlines, process cleanup, and stdout/stderr capture; continue other targets on failure and retain issued certificates.
- **CLI** — Select DNS profiles interactively for issuance and `provider show/cleanup/remove`; complete missing `provider add` fields on terminals. Edit provider executable, arguments, and allowed zones through a draft menu when `update` has no explicit changes; return from submenus without losing draft changes, save once with a complete snapshot check, and discard canceled drafts. Explicit update flags retain direct execution. Show provider inventory in a shared colored table and expose the profile TOML path in details. JSON and nonterminal calls require explicit inputs. `cert remove NAME --failed` cleans up terminally failed unissued requests while preserving issued, resumable and uncertain operations. Interactive input, scoped arguments, offline inventory, metadata-only account inspection without private keys, explicit CA verification, shared UTC progress/tables, JSON reports, build metadata, and safe debug stages. Manual action reports include the exact operation ID in both text and JSON recovery commands. Configure request timeout, operation timeout, poll interval, and poll limits independently; show poll counts and Retry-After wait sources. Resolve the shared state root with `--data-dir`, `ASTER_ACME_DATA_DIR`, then the platform default.
- **CAA prechecks** — Advisory checks before new orders in issue/renew, using advertised CA identities, inherited CAA policy, wildcard precedence and account/method constraints. Unmatched records, unknown extensions, DNS failures and timeouts never block CA validation. Feature-gated, explicitly invoked CAA/TXT/HTTP checkers share the embeddable runner, default five-second stage budget and cancellation policy, with structured reports retaining partial observations. Preserve system-resolver initialization stages and underlying causes in CAA/TXT diagnostics; distinguish missing CA identities from local initialization failures. Keep system DNS configuration and upstream Hickory unchanged, without fallback resolvers. Libraries default to no prechecks; CLI enables them by default.
- **Protocol diagnostics** — Typed ACME resources and all 32 IANA error types with RFC/draft references, unknown-extension preservation, identifier subproblems, exact ARI explanationURL mapping, bounded expiry-spanning renewal windows, and persisted rejection/uncertainty evidence. Check the live IANA registry weekly.
- **Embedding and documentation** — Object-safe signer/store/solver/observer contracts, named per-method material modules, centralized method admission/publication policies, typed retained-validation snapshots, project and CLI contracts, task routing, module design guides, RFC references, and separate local/staging validation records.
- **Repository governance automation** — Adopt the organization-shared, SHA-pinned `AsterCommunity/aster-automation` Action with repository-owned `.github/aster-automation.json`: path-proven labels (`Rust`, `Python`, `Documentation`, `Dependencies`, `Scope: Core|Protocol|Client|Crypto|Challenges|Storage|CLI|Deployment`, `Risk: High` including the `crypto.rs`, `transport.rs` and `storage.rs` module roots), linked-issue lifecycle (`Priority:*`, `Status:*`, `Wait For PR`, `Merged`), an aggregated `PR Gate` with CI lifecycle labels and in-place diagnostic comments, fingerprinted default-branch/scheduled failure issues with flaky and infrastructure classification, hourly reconciliation that also syncs label definitions, issue templates that pre-tag new reports, and a release readiness dashboard. Serialize all shared-action label writers through a FIFO workflow queue; distinguish same-SHA CI workflow runs. `Repository Automation` validates the configuration and workflow concurrency/path contract.

### Changed

- **DNS cleanup and propagation** — Save provider receipts, wait 5 seconds, and check each TXT owner once with a default 5-second advisory budget, requiring all expected values from the same answer. Confirmed values proceed immediately; missing values, resolver errors and probe timeout add a 10-second grace period before CA validation. Report DNS cleanup progress without turning an issued certificate into failure. Existing profile propagation settings now control the initial delay and single-probe budget; explicit values are retained. Preserve partial external-provider cleanup results, honor persisted retry limits after receipt recovery, and allow cleanup only after a confirmed terminal outcome or an expired pending/ready order whose finalize was never submitted; deterministic CSR rejection is eligible. Keep uncertain finalize results protected from DNS cleanup and journal removal.
- **Recovery and concurrency** — Carry explicit shared account leases through blocking writes; classify signer-stage and execution-stage account contention identically so lock waits do not increase renewal failure backoff. Serialize rollover IO, retain submission ownership through caller cancellation, and bind confirmations to the inspected identity. Reconcile confirmed rollover locally through the account service, preserve old challenge material across account key changes, restore certificate views from the durable catalog, and reject stale promotion. Derive stable account IDs in the library and share DNS owner validation between provider profiles and DNS routing. Bound optional before-order advice by cancellation and operation deadline. Keep expired requests with an unconfirmed finalize result, and carry the later creation/finalize rejection Retry-After into the predecessor retry report and honor it before creating a new renewal generation. Keep foreground renewal admission, retained-child submission barriers, pending-generation deployment admission, checkpoint transitions and retry deadlines in library policy; preserve timestamp precision and compare the complete leased binding before storage writes. Report renewal admission failures separately from filesystem errors. Run ARI, due renewal, and deployment retry stages through the library maintenance coordinator; keep filesystem leases in storage and reload execution in the host. Share cancellation/deadlines through CA discovery and automatic deployment; persist known reload failure backoff when cancellation arrives between retry attempts; preserve committed batch results.
- **Publication and cleanup** — Deploy regular files at stable directory paths without links, directory swaps, or a whole-set atomicity guarantee. Pin webroot directory identities with rename-blocking Windows sharing access, sync new directory permissions, and drain blocking workers on shutdown; reuse the HTTP pool for advisory probes, honoring operator proxies and internal destinations with a shared fixed five-second DNS/HTTP precheck budget; accept trailing ASCII whitespace in HTTP-01 responses. Webroot cleanup verifies the actual isolated object before deletion and retains user replacements. Manual validation confirms with visible input/editing and default no, using a scoped terminal reader that polls cancellation, shutdown and deadlines even while idle. Readers restore terminal mode on their own thread and are joined before returning; diagnostic write/flush failures cannot report success.
- **Storage and portability** — Versioned TOML, bounded typed queries, standard-library locks, and platform-specific file validation. Unix uses private permissions and relative internal in_use links; Windows uses inherited permissions and recoverable complete-directory copies. Sync new Unix state-directory entries before remote mutations; never recreate deleted accounts through metadata saves. Windows process-restart recovery does not imply power-loss durability of rename metadata. Preserve unrelated user files.
- **Runtime and dependencies** — Share lazy HTTP connections while isolating account policy and nonce state. Centralize dependency versions/features and enforce rustls/AWS-LC. Optimize release size and install the Forge panic hook only in the executable, with private redacted reports and no mutation retries.
- **Build and CI** — Apply a seven-day cooldown when resolving new registry versions while retaining existing lockfile entries. Check Linux, macOS, and Windows; enforce import ownership, dependency features, and local documentation links and independent optional-precheck feature combinations, including proof that libraries with disabled prechecks exclude the DNS resolver (CLI external DNS retains its independent resolver). Decode source, manifests, and Cargo output as UTF-8 independently of Windows locale. Avoid unrelated parent-repository revisions and missing packed-reference watch paths; build dirty covers tracked changes only. A Linux coverage job collects `cargo-llvm-cov` LCOV output, publishes a per-run summary, and uploads it to Codecov.

Cross-compilation and local mocks do not constitute native-platform or public-CA acceptance.
