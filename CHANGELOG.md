# Changelog

## [Unreleased]

### Added

- Complete manual DNS-01 issuance via `cert issue`, primary-domain certificate names, readable timestamped generations with stable current paths and separate full-chain/leaf/CA/private-key PEM artifacts, fixed certificate keys/CSRs, interactive or structured TXT publication requirements, optional local Hickory DNS checks (`--force` skips only those checks), persisted resume by name with explicit request selection for ambiguity, expiry-aware state decisions, bounded foreground polling, issued SAN/key/validity checks, and atomic current-generation promotion. A single `-c manual_dns` selects verification; the validation crate organizes implementations by challenge method. Read-only `cert list/show` includes request times and separate order/authorization/certificate expiry; `--verify` never advances issuance. Interactive missing-input guidance, concise request selection, aligned colored details/tables, shared output/log/time/table components, compact request selectors, fixed UTC times, versioned help headings and aligned build information, typed progress events and accurate verification markers support both terminal and JSON use. Extra non-managed directory contents are preserved. Unknown challenge extensions are retained without requiring DNS-01-specific fields. Automated DNS publication, renewal and deployment remain unavailable.

- Dedicated `aster_acme_protocol` crate centralizes typed request/response, public provider directory presets, discovered URL, problem and JWS contracts. Protocol requests and CLI JSON reports serialize named structures; callers import models directly without legacy re-exports.
- ACME account registration, key-based recovery, authenticated inspection, contact replacement/clearing, recoverable key rollover, and irreversible deactivation with durable uncertain-result handling with ES256 JWS, explicit terms acceptance, HS256 EAB, bounded badNonce retries, response limits, timeouts, and structured CA errors. Pure core decisions drive account lifecycle eligibility and transitions. UTC registration-confirmation, status-observation, and last-use timestamps update only on successful account responses. Local contact settings are retained separately from optional CA contact responses. Object-safe signer/store interfaces support embedded services.
- CLI account commands including `update-contact` and `rotate-key`, with public CA presets and custom `--ca-directory`, production Let’s Encrypt defaults, unified data-directory configuration, command-scoped flags, shared interactive account selection with a create-first registration action menu, explicit account-scoped User-Agent with per-command overrides and non-persisted built-in defaults, plain-email contact input normalized to ACME URIs, boolean consent recording the discovered terms URL, aligned account listing with highlighted default selection and optional per-account verification, offline inspection with explicit `--verify`, shared positional/named account targets, local-only account removal, concise action summaries, named accounts bound to individual CAs with comment-preserving default switching, successful registration conditionally restores an absent default without overriding another selection; existing-account commands validate local identity before prompts/network work. Explicit reuse notices and default-no interactive account reuse and current-terms confirmation, optional validated email prompts (`--yes` for reuse in automation, separate `--accept-terms` for consent), platform default unified state directory with automatically initialized versioned TOML configuration and persisted explicit registration contacts, colored terminal diagnostics, structured JSON output, and a version command exposing build-time revision, dirty state, target, profile, features and timestamp. A separate Unix file-storage adapter with private PKCS#8 keys, versioned TOML metadata and account selection, one directory per local account name containing its key and metadata, CA/key identity checks, bounded AsterFs locking, and Forge descriptor-based atomic state writes. Interrupted registration retains its key and intent for recovery; missing initialized account keys are never silently replaced.

- Pure ACME resource-state decisions and upper-layer DNS identifiers, challenge selection/material derivation, and injectable solver contracts with versioned recovery receipts. Known and unknown wire values, input boundaries, and selection combinations have regression coverage; manual DNS issuance is implemented while automatic publication and HTTP/TLS solvers remain unimplemented.

- Rust workspace packages and crate directories use underscore names; the executable remains `aster-acme`. Workspace includes protocol core, client orchestration, validation implementations, and CLI crate boundaries. Rustls and a shared AWS-LC crypto backend avoid duplicate P-256 stacks, with a CI check excluding native-tls/OpenSSL transports. HTTP pools and request execution use pinned Forge HTTP; ACME retains typed reqwest response/error handling and protocol retry policy. Dependencies and Forge-aligned strict lints are managed at the workspace root. The CLI bin disables rustdoc output to avoid colliding with the library while retaining its executable name. Each crate owns its explicit package version; dependency versions and features remain workspace-owned. Renewal and revocation are not implemented yet.
